## Prerequisite (owner action, not code)

GitHub publishes a *project* repo at `songer522.github.io/songer-home-page/`, not at the
root. To land at the root, the owner must **rename this repo to `songer522.github.io`** in
GitHub repo settings (GitHub redirects the old URL automatically), and set
Settings → Pages → Source to **GitHub Actions**.

Build for the root (`base` omitted, defaults to `/`). If the owner decides to keep the
current repo name, the only change is adding `base: '/songer-home-page'` to
`astro.config.mjs`. **Confirm which before the first deploy** — this is the one setting
that silently breaks every asset URL if it is wrong.

## Architecture

Astro static site → GitHub Actions build → GitHub Pages. No server, no database, no CMS.
The only runtime JavaScript on the entire site is the click-to-load video embed facade.

Route map — Chinese at the root, English mirrored under `/en/`:

```
/                /en/                landing: profile sidebar + featured cards
/apps/           /en/apps/           full app list
/apps/<slug>/    /en/apps/<slug>/    app detail page
/videos/         /en/videos/
/videos/<slug>/  /en/videos/<slug>/  video detail page
/about/          /en/about/
/blog/  → existing external blog, linked in nav, not built by this project
```

Routing is **directory-based** (explicit `src/pages/en/…` files), not generated by Astro's
i18n routing middleware. The `i18n` block in the config is present so `astro:i18n` helpers
and `hreflang` work correctly, but the pages themselves are real files. This is more code
than dynamic locale routing and is the right trade: it keeps every URL greppable and lets
the two locales diverge later without a rewrite.

### Step 3 — Content schemas: `src/content.config.ts`

Two collections, not one, because apps and videos carry genuinely different fields.
Same slug in both locale folders = the same project in two languages.

```ts
import { defineCollection, z } from 'astro:content';
import { glob } from 'astro/loaders';

const apps = defineCollection({
  loader: glob({ pattern: '**/*.md', base: './src/content/apps' }),
  schema: z.object({
    title: z.string(),
    summary: z.string(),                          // one line, shown on the card
    status: z.enum(['live', 'wip', 'free-tool']),
    tags: z.array(z.string()).default([]),
    cover: z.string(),                            // e.g. /images/placeholders/app-1.svg
    links: z.array(z.object({
      label: z.string(),
      url: z.string(),
    })).default([]),                              // App Store + GitHub + site, etc.
    featured: z.boolean().default(false),
    order: z.number().default(0),
  }),
});

const videos = defineCollection({
  loader: glob({ pattern: '**/*.md', base: './src/content/videos' }),
  schema: z.object({
    title: z.string(),
    summary: z.string(),
    platform: z.enum(['youtube', 'bilibili']),
    videoId: z.string(),
    cover: z.string(),
    publishedAt: z.coerce.date(),
    featured: z.boolean().default(false),
  }),
});

export const collections = { apps, videos };
```

With the `glob` loader rooted at the collection directory, an entry at
`apps/zh/focus-timer.md` gets the id `zh/focus-timer`. **The locale is the first id
segment and the slug is the rest** — every query and every `getStaticPaths` depends on
this. Helpers:

```ts
export const localeOf = (id: string) => id.split('/')[0];
export const slugOf   = (id: string) => id.split('/').slice(1).join('/');
```

Put these in `src/i18n/utils.ts` (Step 4) so pages import them from one place.

`cover` is deliberately a **plain string path** into `public/images/`, not Astro's
`image()` schema helper. Placeholder art is SVG, and `image()` adds build friction for no
benefit until real raster screenshots exist. Migrating to `image()` is a clean follow-up
once the owner supplies real assets — note it in the README.

`src/i18n/utils.ts`:

```ts
import { ui, defaultLocale, type Locale } from './ui';

export const localeOf = (id: string) => id.split('/')[0] as Locale;
export const slugOf   = (id: string) => id.split('/').slice(1).join('/');

export function t(locale: Locale) {
  return (key: keyof typeof ui['zh']) => ui[locale][key] ?? ui[defaultLocale][key];
}

/** '/en/apps/foo/' -> 'en';  '/apps/foo/' -> 'zh' */
export function getLocaleFromUrl(url: URL): Locale {
  return url.pathname.split('/')[1] === 'en' ? 'en' : 'zh';
}

/**
 * Map the current path to its counterpart in the other locale.
 *   '/'              <-> '/en/'
 *   '/apps/'         <-> '/en/apps/'
 *   '/apps/foo/'     <-> '/en/apps/foo/'
 * Must round-trip: switchLocalePath(switchLocalePath(p, 'en'), 'zh') === p
 */
export function switchLocalePath(pathname: string, to: Locale): string {
  const isEn = pathname.startsWith('/en/') || pathname === '/en';
  const bare = isEn ? pathname.replace(/^\/en/, '') || '/' : pathname;
  return to === 'en' ? (bare === '/' ? '/en/' : `/en${bare}`) : bare;
}
```

This function is the fiddliest pure logic in the project and the thing most likely to be
subtly wrong (trailing slashes, the root case, the bare `/en` case). It gets unit tests in
Step 10.

### Step 5 — Layout and components

`src/layouts/BaseLayout.astro` — props `{ title, description, locale }`. Renders
`<html lang={locale === 'zh' ? 'zh-CN' : 'en'}>`, charset/viewport, `<title>`,
meta description, Open Graph + Twitter card tags built from `Astro.site`, and
`<link rel="alternate" hreflang>` pairs pointing at both locale versions of the current
page (use `switchLocalePath`). Imports `src/styles/global.css`. Slots in `Nav` above and
`Footer` below the content slot.

`src/components/Nav.astro` — logo/wordmark linking to the locale home, links to Work /
Videos / About, an external link to `https://songer522.github.io/blog/`, and the 中/EN
switcher. **The switcher is two plain `<a>` tags built with `switchLocalePath`, not
JavaScript** — from an app detail page it must land on the same project in the other
language, not on the home page.

`src/components/ProfileCard.astro` — sticky on desktop (`position: sticky; top: 2rem`),
static on mobile. Avatar image, greeting line, a two-line positioning statement, a row of
topic tags, and a row of social icon links. All placeholder.

`src/components/ProjectGrid.astro` — CSS grid, `repeat(auto-fill, minmax(280px, 1fr))`,
single column below 720px. Takes a slot.

`src/components/ProjectCard.astro` — props `{ href, title, summary, status?, cover?,
cta }`. Status badge top-right, title, one-line summary, CTA link with a `→`. The whole
card is a link; keep exactly one focusable anchor per card so keyboard tab order stays
sane.

`src/components/VideoEmbed.astro` — props `{ platform, videoId, cover, title }`. Renders
a **click-to-load facade**: the cover image plus a play button, and only on click does it
swap in the iframe. This keeps YouTube/Bilibili trackers off the page until the visitor
actually asks for the video, and keeps the page fast.

```
youtube:   https://www.youtube-nocookie.com/embed/{videoId}?autoplay=1
bilibili:  https://player.bilibili.com/player.html?bvid={videoId}&autoplay=1
```

Use an inline `<script>` scoped to the component, with a `<button>` (not a div) as the
trigger so it is keyboard accessible. This is the only JS on the site.

`src/components/Footer.astro` — one placeholder line plus a link back to the blog.

### Step 6 — Pages

Twelve page files. Every page: read the locale, get `t(locale)`, query the collection
filtered to that locale, render.

**`src/pages/index.astro`** (and its `en/` twin):
```ts
const locale = 'zh'; // 'en' in the en/ twin — explicit, not inferred
const apps = (await getCollection('apps', ({ id }) => localeOf(id) === locale))
  .filter(a => a.data.featured)
  .sort((a, b) => a.data.order - b.data.order);
```
Two-column layout: `ProfileCard` left, featured `ProjectGrid` right, then a recent-videos
strip, then a "view all" link to `/apps/`.

**`src/pages/apps/index.astro`** — all apps for the locale, sorted by `order`.

**`src/pages/apps/[slug].astro`** — detail page:
```ts
export async function getStaticPaths() {
  const entries = await getCollection('apps', ({ id }) => localeOf(id) === 'zh');
  return entries.map(entry => ({ params: { slug: slugOf(entry.id) }, props: { entry } }));
}
const { entry } = Astro.props;
const { Content } = await render(entry);   // import { render } from 'astro:content'
```
Renders cover, title, status badge, tags, the Markdown body, and the `links` list.
The `en/` twin is identical but filters `=== 'en'`.

**`src/pages/videos/index.astro`** and **`[slug].astro`** — same pattern, sorted by
`publishedAt` descending, detail page using `VideoEmbed`.

**`src/pages/about.astro`** — placeholder bio, static content, both locales.

### Step 9 — Deploy workflow

`.github/workflows/deploy.yml`:

```yaml
name: Deploy to GitHub Pages
on:
  push:
    branches: [main]
  workflow_dispatch:
permissions:
  contents: read
  pages: write
  id-token: write
concurrency:
  group: pages
  cancel-in-progress: true
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: withastro/action@v3
  deploy:
    needs: build
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      - id: deployment
        uses: actions/deploy-pages@v4
```

| input | to | expected |

## Error handling

Three build-time guards, all failing loudly rather than shipping broken pages:

1. **Zod schema validation** on every content file — a typo'd `status` value fails the
   build instead of rendering an unstyled badge.
2. **`astro check`** for type errors across `.astro` and `.ts`.
3. **Locale-parity test** — every `zh` slug has an `en` counterpart and vice versa.

External links are deliberately **not** build-blocking. A dead App Store link should not
break a deploy.
